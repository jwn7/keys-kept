# 보안 설계: 무엇을 막고, 무엇으로 막는가

위협 모델 한 줄 요약은 `docs/SPEC.md` §7. 이 문서는 요즘 실제로 일어나는 공격별로 이 앱의 대응과, 앞으로 넣을 "우리만의" 방어를 적는다.

## 원칙: 암호 알고리즘은 만들지 않고, 조합을 설계한다
- 새 암호 알고리즘(원시 함수)을 만드는 것은 독특함이 곧 약점이다. 공개 검증을 수년간 버틴 것만 쓴다: `libsodium`의 Argon2id, XChaCha20-Poly1305 (CLAUDE.md 규칙 1, 유지).
- 차별점은 그 위층에서 만든다: 검증된 부품을 **어떻게 조합해 무엇을 막는가**. 아래 "제안"은 전부 표준 부품의 조합이다.
- 주장은 확인할 수 있어야 한다. 막는다고 쓴 것은 테스트나 스크립트로 재현한다.

### CSP가 실제로 막는지 확인하는 법
```
pnpm --filter @vault/web build
pnpm --filter @vault/web preview        # 다른 터미널
node apps/web/scripts/csp-check.mjs
```
배포 빌드에서 앱을 한 바퀴 돌려 정책 위반이 없는지 보고, 끼어든 스크립트인 척 `fetch`·이미지·바깥 스크립트·`eval`을 시도해 전부 막히는지 본다. CI의 e2e 작업에서도 돌린다.
개발 서버(`pnpm dev`)에는 CSP가 없다(HMR이 인라인 스크립트를 쓴다).

## 키를 꺼내 쓸 때 (`packages/env`)
- 평문 `.env`를 디스크에 두지 않는다: 앱이 표준 age 파일(`.env.age`)로 내보내고, `vault-run`이 풀어 실행하는 프로그램의 환경변수로만 넣는다.
- AI 코딩 도구에는 값을 주지 않는다: MCP 서버의 도구는 이름 목록, 이름을 골라 실행, 없는 키 요청뿐이다. 실행 결과에 값이 찍히면 가린다.
- 한계: 실행한 명령이 값을 내보내는 것은 못 막는다. 가리기는 값과 똑같은 글자열만 잡는다. MCP용 파일 비밀번호는 지금 설정 파일에 평문으로 들어간다.
- 앱 화면에서는 값을 항상 가려서 보이고, 복사한 값은 30초 뒤에도 클립보드가 그대로일 때만 지운다. 평문 내보내기(옵시디언 zip)에는 값을 넣지 않는다.

## 넣은 방어의 범위와 한계 (2026-11)
### 크기 감추기
- 평문(메모 JSON) 뒤를 공백으로 채운다. JSON 뒤 공백은 해석에 영향이 없어서 **형식 버전이 그대로**다: 예전 암호문도, 채우기를 모르는 옛 앱도 서로 읽는다.
- 예전에 저장된 메모는 다음에 고칠 때 채워진다(일괄 재암호화는 하지 않는다).
- 여전히 보이는 것: 메모 개수, 수정·삭제 시각, 버전 번호, 기기 id, 그리고 큰 구간 단위의 크기. 백업 파일(age) 전체 크기는 감추지 않는다.

### 되돌리기 감지
- 기준은 이 기기의 로컬 저장소다("내가 본 최신 버전"). 따로 저장하는 것은 없다.
- 평소 동기화는 바뀐 것만 받으므로, 24시간에 한 번 전체를 다시 받는다. Drive에서는 메모 수만큼 요청이 나간다.
- 전체를 다시 받을 때 예전에 이미 받아 본 암호문은 nonce로 알아보고 충돌로 치지 않는다.
- 못 잡는 것: 서버가 새 수정을 **숨기기만** 하는 경우(이 기기는 그런 수정이 있는 줄 모른다), 이 메모를 한 번도 받은 적 없는 새 기기에 옛 버전을 주는 경우. 기기들이 서로의 상태 요약을 주고받아야 잡을 수 있다(아래 제안 1).
- 알림 문구는 "공격"이라고 단정하지 않는다. 동시 쓰기 경합으로도 같은 일이 생길 수 있다.

## 다음 방어 (전부 보류, `docs/STRATEGY.md`)

1. **기기 간 상태 요약**: 각 기기가 "내가 가진 항목 id와 버전의 해시"를 암호화해 서버에 올리고 다른 기기가 비교한다. 숨기기와 새 기기 되돌리기까지 잡는다.
2. **열쇠 확약(key commitment)**: XChaCha20-Poly1305는 한 암호문이 여러 열쇠로 풀리게 만들 수 있다. 악성 서버가 조작한 열쇠 기록으로 비밀번호 후보를 한 번에 여러 개씩 걸러내는 공격(partitioning oracle)의 여지를 없애려면, 감싼 열쇠에 열쇠의 해시(`crypto_generichash`)를 같이 두고 확인한다.
3. **가짜 금고(강요 대응)**: 다른 비밀번호를 넣으면 다른 메모 묶음이 열린다. 누가 강제로 열게 해도 진짜가 따로 있다는 것을 증명할 수 없게 한다. 메모 앱에서는 드문 기능이고 설명하기 쉽다. 설계가 가장 크다(항목 수로 들키지 않게 하려면 크기 채우기와 가짜 항목이 같이 필요).
4. **빌드 지문**: 실행 중인 앱 파일들의 해시를 설정에 보여주고, 같은 값을 공개 저장소의 릴리스에 올린다. 서버가 코드를 바꿔 내려보내면 지문이 달라진다. 서버가 지문 표시까지 속일 수 있으므로 완전한 해결은 아니고, 제3자가 감시할 수 있게 하는 장치다.

## (보류) 뜻 색인을 넣게 되면 지켜야 할 것
임베딩 벡터에서 원문을 거의 복원할 수 있다(연구로 확인됨). 그래서 벡터는 메모와 똑같이 itemsKey로 암호화하고 `sync/`로만 내보낸다. 모델 파일은 받기 전에 크기와 출처를 알리고, 받은 뒤 해시를 확인한다. 추론 중에는 네트워크 요청이 없어야 한다(CSP가 이미 강제).
