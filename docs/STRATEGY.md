# 방향과 계획 (하나로 정함, 2026-11-25)

방향을 바꾸려면 이 문서를 먼저 고친다. 다른 문서가 이 문서와 다르면 이 문서가 맞다.

## 이 앱은 무엇인가
**1인 개발자와 바이브코더를 위한 키 장부.**
API 키, 환경변수, 계정 정보를 메모장에 적어 두는 대신, 안전하게 보관하고 "어디에 쓰이는지, 언제 끝나는지, 털리면 뭘 바꿔야 하는지"를 같이 관리한다.

- 누구: 혼자 만들고 배포하는 사람. AI로 빠르게 만들다 보니 키가 금방 열 개를 넘고, 어디에 넣었는지 모르고, 실수로 공개하기 쉽다.
- 처음 만든 이유: 중요한 값을 그냥 메모장에 적는 대신 제대로 관리하는 도구가 필요해서. 메모 앱이 목적이 아니었다.

## 차별점: 보관이 아니라 장부, 그리고 AI에게 안 보여주고 쓰기
1Password, Bitwarden, Doppler, Infisical은 "어디에 안전하게 두느냐"를 푼다. 여기서는 못 이긴다.
비어 있는 곳은 **사고가 났을 때**다. 노트북이 악성코드에 걸렸거나 키를 깃허브에 올렸을 때 "지금 뭘 바꿔야 하지"에 답하는 개인용 도구가 없다.

- **키를 알아본다**: 붙여 넣으면 모양을 보고 어느 서비스의 무슨 키인지, 운영용인지, 공개돼도 되는 키인지 표시한다.
- **실수를 미리 막는다**: `NEXT_PUBLIC_`·`VITE_`처럼 브라우저에 공개되는 이름에 비밀 키를 넣으려 하면 경고한다. 바이브코더가 가장 자주 하는 사고다.
- **쓰이는 곳을 적는다**: 이 키가 어느 프로젝트, 어느 기기, 어느 배포 환경에 들어가 있는지.
- **만료를 챙긴다**: 끝나기 전에 첫 화면에 올라온다.
- **사고 모드**: "이 노트북이 털렸다"를 누르면 그 기기에 있던 키만 골라 교체 체크리스트를 만들고 각 서비스의 재발급 페이지로 보낸다.
- **AI에게 키를 보여주지 않고 쓰게 한다**: AI 코딩 도구가 키가 필요할 때 값이 아니라 이름으로 요청하고, 값은 실행 환경에만 들어간다 (계획 4).

바탕은 그대로다: 기기에서 암호화, 회사 서버 없이 내 드라이브에 암호문만, 무료.

## 계획 (이 순서대로, 다른 것은 끼워 넣지 않는다)
1. **키 알아보기** (core, 화면 없음): 키 모양 인식, `.env` 읽기와 쓰기, 공개 이름에 비밀 키 경고. ← 지금
2. **키 항목**: 메모에 키 값·종류·환경·쓰이는 곳을 담는다. 프로젝트 = 폴더, 만료일 = 날짜(이미 있는 기능).
3. **화면과 꺼내 쓰기**: 넣기만 쉬우면 결국 메모장으로 돌아간다. 꺼내는 길을 짧게 만든다.
   - 값은 가려서 보이고, 누르면 복사, 잠시 뒤 클립보드에서 지운다.
   - **`Ctrl+K` → 이름 몇 글자 → Enter = 값 복사.** 앱을 열고 키 입력 두세 번으로 끝난다. `Shift+Enter`는 `NAME=value` 꼴로 복사.
   - 프로젝트 하나를 통째로: `.env` 내용 복사, 또는 `.env` 파일로 내려받기. 환경(개발·운영)을 골라서.
   - 넣을 때: `.env`를 붙여 넣으면 항목으로 나뉜다.
4. **꺼내 쓰는 패키지** (복사·붙여넣기 없이 코드가 직접 받아 간다):
   - 앱이 프로젝트의 값을 암호화된 파일 하나(`.env.age`, 표준 age 포맷)로 내보낸다. 평문 `.env`는 디스크에 두지 않는다. 2026년의 npm 웜들이 훔쳐 간 것이 바로 디스크의 `.env`다.
   - 명령줄: `vault-run -- npm run dev` 처럼 감싸 실행하면 비밀번호를 한 번 묻고, 값을 풀어 그 프로그램의 환경변수로만 넣는다.
   - 코드에서: `dotenv`처럼 한 줄로 불러 쓴다(`import '@vault/env/load'`).
   - 접속 정보처럼 여러 값이 한 묶음인 것(호스트·포트·사용자·비밀번호)은 묶음째 꺼낸다.
   - `packages/core`가 이미 Node에서 도는 것을 그대로 쓴다. 새 암호 방식은 없다.
   - **AI 코딩 도구와 연결 (MCP)**: AI가 "이 키를 넣어 주세요"라고 할 때 채팅에 붙여 넣지 않는다. AI는 금고에 **이름으로만** 요청하고, 사용자가 승인하면 값은 실행하는 프로그램의 환경변수로 바로 들어간다. AI가 받는 것은 "넣었음"과 실행 결과뿐이고, 결과에 값이 찍히면 가려서 돌려준다.
     - 왜: 키를 AI 채팅에 붙여 넣으면 그 회사 서버에 남는다. 2026년 노션 AI 유출에서 실제로 채팅에 붙여 넣은 API 키들이 노출돼 폐기됐다.
     - AI에게 주는 도구: 키 이름 목록 보기, 이름을 골라 명령 실행, 없는 키를 사용자에게 요청하기. 값을 돌려주는 도구는 만들지 않는다.
     - 한계: 실행한 프로그램이 값을 다른 곳으로 보내는 것까지는 못 막는다. 승인 창에 어떤 명령에 어떤 키가 들어가는지 보여준다.
5. **첫 화면을 장부로**: 곧 만료, 경고가 있는 키, 최근에 쓴 키. (오늘 화면을 고친다)
6. **사고 모드**: 기기나 프로젝트를 고르면 교체 체크리스트. (할 일 모음을 고친다)
7. **출시 준비**: `docs/ROADMAP.md` 5단계. 다국어(`en.ts`)는 여기서.

## 다음 계획: 개발 흐름에 붙이기 (2026-11-25 추가, 1~6단계 완료 뒤)
방향은 그대로 키 장부다. 다른 도구들을 조사해 쓸모가 확인된 것만 골랐다(Infisical의 브랜치 연결·개인 값, Varlock의 스키마 대조·유출 검사, Doppler의 동기화).

8. **환경 비교표와 화면 개편**: 키를 행, 환경을 열로 놓고 빠진 칸을 바로 보여준다. "운영에 변수 하나가 빠져서 장애"가 가장 흔한 사고다. 프로젝트 화면의 기본 모습을 이 표로 바꾼다.
9. **키 생성기**: 세션 비밀값·웹훅 비밀값처럼 내가 정하는 값을 안전한 난수로 만든다.
10. **개발 흐름 연결** (`packages/env`):
    - 깃 브랜치 → 환경: `main`이면 prod, 나머지는 dev 식으로 `.vault.json`에 적어 두면 `vault-run`이 알아서 고른다.
    - `vault-check`: 저장소의 `.env.example`이 요구하는 이름이 금고에 다 있는지 실행 전에 확인.
    - `vault-scan`: 커밋하려는 파일에 금고의 **실제 값**이 들어 있으면 막는다. 모양으로 추측하는 검사기와 달리 우리는 값을 안다.
    - GitHub Actions 비밀값으로 올리기(사용자의 `gh` 로그인을 빌려 기기에서 바로. 우리 서버를 거치지 않는다).
11. **다른 저장소**: Google Drive 말고 내 컴퓨터의 폴더(다른 동기화 도구와 같이 쓰기), WebDAV, S3. `SyncBackend` 구현만 추가하면 된다(규칙 4).
12. **팀 공유**: 1판(파일로 주고받기)은 만들었다(`docs/TEAM.md`). 아래는 2판(같이 쓰는 프로젝트, 설계 먼저)이다: 프로젝트 열쇠를 멤버의 공개키로 감싸 나눠 준다. 서버는 여전히 내용을 못 본다. 공개키 암호는 libsodium의 것을 쓴다(규칙 1 그대로).
    - 정해야 할 것: 초대와 신원 확인 방법, 멤버를 빼면 열쇠와 키 값을 전부 바꿔야 한다는 점, 누가 무엇을 바꿨는지의 기록, 저장소(공유는 Drive 폴더 공유 또는 Supabase).
    - 한번 넣으면 되돌리기 어렵다. 설계 문서와 공격 테스트를 먼저 쓰고 승인받은 뒤 만든다.
13. **출시 준비**: 영어 화면, Google OAuth 등록, 설치형 빌드.
14. **화면 구조를 프로젝트 먼저로** (2026-11-25 사용자 제안): 잠금을 풀면 프로젝트 목록이 먼저 나오고, 프로젝트 → 환경 → 키 순서로 들어간다. "살펴볼 것"은 첫 화면이 아니라 경고가 있을 때만 프로젝트 목록 위에 뜨는 띠가 된다. 프로젝트가 하나뿐이면 마지막에 본 프로젝트를 바로 연다. 디자인 캔버스에서 먼저 확정하고(1-1 ~ 5-2 보드), 그다음 앱을 고친다. 데이터 구조는 그대로다(폴더가 프로젝트). 같이 정할 것: 메모 기능과 일정·할 일·복습 칸을 남길지.

## 이미 만든 것의 자리
| 만든 것 | 앞으로 |
|---|---|
| 암호화, 잠금·패스키, Drive 동기화, 백업, CSP, 크기 감추기, 되돌리기 감지 | 그대로. 이 도구에 꼭 필요한 바탕 |
| 날짜, 오늘 화면, 할 일 모음, 서버가 보는 모습 | 만료일, 장부 첫 화면, 교체 체크리스트로 다시 쓴다 |
| 자유 메모, 마크다운 편집기 | 키에 딸린 설명과 보안 메모로 남긴다 |
| 캘린더 보기, 복습, 회의록·학습 틀 | 그대로 두되 더 손대지 않는다 |

## 보류 (지금은 하지 않는다. 꺼내려면 이 문서의 계획을 먼저 고친다)
- 저장소 검증 라이브러리, 가짜 금고, 빌드 지문, 열쇠 확약 (`docs/SECURITY.md`)
- 다른 값을 가리키는 참조(`${OTHER}`), 쓰는 순간 만들어지는 임시 자격증명: 팀·서버 기능이 있어야 뜻이 있다
- 기기 안 AI 모델 (`experiments/semantic-search/`)
- 보상 시스템, 다른 앱에서 옮겨 오기
- 브라우저 확장(서비스 화면에서 바로 채우기), 운영 서버에 값 배포하기(Vercel 등 연동): 꺼내 쓰기의 다음 단계
- 패키지가 비밀번호를 매번 묻지 않게 하기(OS 키체인 연동): 패키지 첫 판 다음

## 하지 않는다
- 암호 알고리즘 직접 만들기 (CLAUDE.md 규칙 1)
- 서버·외부 AI에 값 보내기, 서버 검색, 누구나 여는 공유 링크 (팀 공유는 위 계획 12: 종단간 암호화로만)
- 키를 대신 재발급해 주기: 각 서비스에 우리 서버가 로그인해야 한다. 재발급 페이지로 보내 주기만 한다

## 미리 적어 두는 위험
- 메모보다 위험이 크다. 새면 실제 피해가 나고, 잃으면 서비스에 못 들어간다. 외부 검토를 받기 전에는 "검토받지 않음"을 앱과 README에 적는다.
- 키 모양은 서비스가 바꿀 수 있다. 인식은 "아마 이것"이지 보증이 아니다. 모르는 모양은 모른다고 표시한다.
- 사고 모드는 사용자가 "어디에 쓰는지"를 적어 둬야 정확하다. 덜 귀찮게 만드는 것이 승부처다.
