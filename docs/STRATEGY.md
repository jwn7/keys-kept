# 방향과 계획 (하나로 정함, 2026-11-25)

방향을 바꾸려면 이 문서를 먼저 고친다. 다른 문서가 이 문서와 다르면 이 문서가 맞다.

## 이 앱은 무엇인가
**회사 서버 없이 내 드라이브에 두는, 서버를 믿지 않는 암호화 메모장.**

- 회사 서버가 없다: 암호문은 사용자의 Google Drive에 있다. 만든 사람이 사라져도 동작한다.
- 서버를 믿지 않는다: 서버가 읽지 못하게 하는 데서 그치지 않고, 서버가 되돌리거나 숨기거나 끼워 넣어도 알아챈다.
- 믿으라고 하지 않고 확인하게 한다: 서버가 보는 모습 보기, 공개 소스, 표준 포맷 백업.

## 우리가 만드는 기술 (딱 하나)
**믿을 수 없는 저장소 위에서, 데이터가 최신이고 빠짐없다는 것을 기기끼리 확인하는 라이브러리.**

- 풀려는 문제: 종단간 암호화는 "못 읽게"만 보장한다. 서버가 옛 암호문을 다시 주거나, 새 수정을 숨기거나, 기기마다 다른 내용을 보여줘도 대부분의 암호화 앱은 모른다(ETH 취리히, 2024, 암호화 저장소 5곳 분석).
- 만드는 것: 각 기기가 "내가 가진 항목들의 요약과 일련번호"를 암호화해 저장소에 올리고, 다른 기기가 자기 상태와 맞춰 본다. 어긋나면 알린다.
- 지키는 선: 암호 알고리즘은 만들지 않는다. 해시와 인증은 libsodium 것을 쓰고, 우리가 만드는 것은 조합 규칙이다 (CLAUDE.md 규칙 1 그대로).
- 형태: `packages/` 아래 독립 패키지. 앱 없이 혼자 테스트되고, 이 메모 앱이 첫 적용 사례다. Drive·S3·WebDAV처럼 "올리고 내려받기만 되는 저장소"면 붙일 수 있게 한다.
- 정직하게: 외부 검토를 받기 전에는 "안전하다"고 주장하지 않는다. 명세를 공개하고 검토받지 않았음을 적는다.

## 계획 (이 순서대로, 다른 것은 끼워 넣지 않는다)
1. **명세**: 막을 공격 목록, 저장소에 올라가는 것의 형식, 기기가 확인하는 규칙, 못 막는 것. 문서 한 장.
2. **공격 테스트 먼저**: 악성 저장소 흉내기(되돌리기, 숨기기, 되살리기, 기기마다 다른 내용, 끼워 넣기)를 만들고 실패하는 테스트를 쓴다.
3. **구현**: 테스트가 전부 통과할 때까지.
4. **앱에 적용**: `packages/core`의 동기화가 이 라이브러리를 쓴다. 앱에는 "저장소 점검 결과" 한 줄만 보인다.
5. **출시 준비**: `docs/ROADMAP.md`의 5단계(Google OAuth 등록, Android 빌드, 스토어 등록). 다국어(`en.ts`)는 여기서.

각 단계가 끝나면 `docs/ROADMAP.md`에 체크한다.

## 보류 (지금은 하지 않는다. 다시 꺼내려면 이 문서의 계획을 먼저 고친다)
| 보류한 것 | 이유 |
|---|---|
| 기기 안 AI 모델(뜻 검색) | 실험은 통과했지만(`experiments/semantic-search/`) 우리가 만든 기술이 아니고 누구나 붙일 수 있다. 135~219MB를 받아야 한다. 정체성이 아니라 나중의 부가 기능 후보 |
| 가짜 금고, 빌드 지문, 열쇠 확약 | 좋은 방어지만 위 라이브러리와 별개의 일이다. 하나를 끝낸 뒤에 본다 (`docs/SECURITY.md` 제안) |
| 보상 시스템, 다른 앱에서 옮겨 오기, 음성 회의록 | 사용성 개선. 기술을 끝낸 뒤에 본다 |

## 하지 않는다 (보류가 아니라 결정)
- 암호 알고리즘 직접 만들기, 자체 LLM 학습
- 서버·외부 AI에 메모 보내기, 서버 검색, 공유 링크
- 암호화 실시간 공동편집, 팀 기능 (노션·슬랙의 자리다. 겨루지 않는다)
- 포인트·랭킹 (서버가 사용 기록을 알아야 한다)

## 이미 끝난 것 (바탕)
암호화 코어, Drive 동기화, 백업, 웹 앱, 오늘 화면과 할 일 모음, 서버가 보는 모습, 사용 수치, CSP와 공급망 방어, 크기 감추기, 되돌리기 감지(한 기기 기준). 자세한 목록은 `docs/ROADMAP.md`.
